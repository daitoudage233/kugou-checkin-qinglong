# [脚本分享] 酷狗概念 VIP 青龙签到，从此不必每天向“领取”按钮问好

事情是这样的：人类负责听歌，按钮负责被点击，定时任务负责在深夜替大家把这些重复劳动打包带走。本帖这个脚本就是第三位同事。它不会替你挑歌，也不会替你写乐评，但能让“今天还没领 VIP”这件事不再每天准时出现在脑内待办里。

原版是 GitHub Actions 路线，这里改成了青龙可直接运行的版本。没有 `npm install` 连环任务，没有本地 API 常驻，也不要求盯着 token 像盯着即将过期的优惠券。扫一次码，剩下交给定时任务按时上班。

## 这位定时同事具体干什么

- 每天领取听歌相关奖励，免得奖励在角落里等到地老天荒。
- 最多连续领取 8 次概念 VIP。每次会按接口要求等 30 秒，脚本很有耐心，完全没有半夜连点的冲动。
- 查询 VIP 到期时间，让“我到底还有没有会员”不再成为哲学问题。
- 支持二维码登录，登录成功自动保存账号信息。
- 支持账号密码登录，适合手机暂时不在手边的时刻。
- 每周日自动刷新 token，避免凭据悄悄失联后才发现定时任务已经在空气里努力了一周。
- 青龙配置了通知就推送结果；没配置也没关系，日志会把事情交代得明明白白。
- 多账号放在同一个文件里。一个账号临时罢工，其他账号继续完成当天工作。

## 懒人上车方式

把下面三个文件上传到青龙的 `scripts` 目录，或者放进自己的订阅仓库：

```text
kgcheckin_qinglong.js
kgcheckin_qr_login.js
kgcheckin_password_login.js
```

按下面顺序操作，三分钟后你就可以把日常点击任务正式外包：

1. 手动运行 `kgcheckin_qr_login.js`。
2. 脚本会直接在任务日志打印二维码，同时生成 `/ql/data/kugou_login_qr.gif`。
3. 在电脑上打开青龙日志，用手机里的酷狗 APP 扫描二维码；也可以从青龙文件管理中打开 GIF 再扫码。
4. 在 APP 中确认登录。成功后账号自动保存到 `/ql/data/kugou_userinfo.json`。
5. 给 `kgcheckin_qinglong.js` 添加定时任务，例如每天北京时间 01:10：

```cron
10 1 * * *
```

至此就完成了。扫码登录和密码登录只需手动运行，真正需要按时出勤的是签到主脚本。二维码有时效，旧码过期后重新运行扫码脚本生成新码即可。

特别提醒：二维码内容不是普通网页链接。直接用浏览器打开时跳到酷狗下载页，属于页面在认真履行“请用 APP 扫我”的职责，不是浏览器突然决定培养音乐品味。

## 不想扫码？走账号密码通道

在青龙环境变量中临时添加一项：

```text
KUGOU_LOGIN=账号#密码
```

随后手动运行 `kgcheckin_password_login.js`。成功后同样会把登录 token 保存到 `/ql/data/kugou_userinfo.json`。保存完成后建议删除 `KUGOU_LOGIN`，毕竟把密码常驻在环境变量里，多少有点像把门钥匙贴在门上的感觉。

如果账号遇到验证码、设备验证、异地验证等安全限制，密码登录可能会失败。这不是脚本闹情绪，而是平台在认真核验身份。这时请直接改用二维码登录，不要把“再试一次”按成连续剧。

## 已经有 Token 的熟练用户

不想使用任何登录脚本也可以手动配置一个变量：

```text
KUGOU_USERINFO=userid#token
```

多个账号用 `&` 分隔：

```text
账号一#令牌一&账号二#令牌二
```

不过只要 `/ql/data/kugou_userinfo.json` 已经存在，脚本就优先使用文件内容。原因很朴素：周日刷新的新 token 在文件里，不能下一秒又被旧环境变量拉回去重走老路。想强制改用环境变量时，先确认无误后删除该账号文件。

## 定时任务每天到底忙了些什么

签到主脚本会验证账号、领取听歌奖励、依次领取 VIP、查询到期时间，然后把结果整理成汇报。每次 VIP 领取成功会等 30 秒，因此一个账号跑几分钟属于正常情况。它不是卡住了，只是在认真等待下一次操作的合法登场。

当天已经领取过的奖励会显示为已领取或已达上限，不会因为“今天不用再领”就把任务演成红色失败警报。

账号数据保存在：

```text
/ql/data/kugou_userinfo.json
```

这个文件包含 token，不要提交到仓库、不要发到群里、不要截图时顺手带上它。脚本日志会对账号和昵称脱敏，密码和 token 不会主动打印。凭据负责安静躺着，脚本负责安静工作，大家都省心。

## 本帖参考了谁

核心签到流程参考了 [develop202/kgcheckin](https://github.com/develop202/kgcheckin)，原项目把 GitHub Actions 的签到流程整理得很完整；这里主要做了青龙适配、凭据持久化和二维码展示。

酷狗接口实现参考了 [MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)。能站在现成接口实现的肩膀上，就不必为了一个签名算法在深夜和十六进制字符谈心。

扫码脚本内嵌了 [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) `v2.0.4` 的 MIT 许可二维码编码实现，用于在本地生成二维码，不会把短期登录二维码扔给外部二维码服务。

## 收工前的几句

脚本只是把重复操作交给定时器，不会改变账号活动规则，也不能绕过平台安全限制。登录失败时优先重新扫码，接口异常时先看日志，再决定是否继续使用。

请合理使用，支持正版。自动化的目标是让人少点几次按钮，不是让定时任务比本人还勤快。
